## 已核验的关键结论

### 1. 强 AI 的瓶颈是高质量、海量对局，而不是先堆大网络

Suphx 先建立监督策略，再以分布式 RL 改进；其论文还指出，只有弃牌模型进入 RL
训练，其他动作模型保留监督版本。Kanachan 同样把「牌谱标注 → 模仿学习 → 更抽象的
奖励目标」分成课程。这说明本项目应先把完整、无泄漏、可回放的厦门对局数据和
同牌墙评测做好，再扩张模型。

### 2. 厦门麻将必须使用规则引擎动作掩码

金、白板代理、手持金不能点炮、金弃不可响应、荣牌跟打、游金封闭圈和多家付款等
规则让固定动作 ID 很容易失效。网络输出应当是每个*当前合法候选动作*的分数；引擎
负责生成候选、执行与计分。这一原则已用于现有 MLP，后续 PyTorch 模型也不得破坏。

### 3. 训练目标须同时覆盖单局得分与跨局牌局目标

Suphx 的全局奖励预测用于把多局累计排名反馈分配给局内决策。厦门经典规则有庄家
连庄与累计分数，因此强化学习第二阶段应先优化每局净得分，然后再引入固定长度牌局
的最终名次/累计分差价值头；不要在单局引擎尚未验证时直接优化抽象排名。

### 4. oracle 只能用于训练辅助，不能泄漏到线上策略

可在训练时给评论家（critic）或辅助预测器加入完整牌墙、各家暗牌等 privileged
information，再通过蒸馏或逐步移除该信息得到仅见信息的 actor。这是 Suphx 的
oracle-guiding 思想。线上动作网络、离线验证和网页试玩必须始终只看玩家手牌与公开
信息。

## 不直接采用的路线

- 不把日麻预训练权重迁移到厦门麻将：动作语义、手牌张数、金牌与结算结构不匹配，
  很难验证收益，且可能带来许可与数据来源问题。
- 不在当前 CPU 单局 Python 引擎上直接进行大规模 PPO：吞吐量会掩盖算法问题。先做
  正确性回放和小规模 DAgger；需要规模化时再实现纯函数、批量化的训练环境。
- 不把 MuZero/MCTS 作为第一阶段：不完全信息下需要确定化/信念建模，且厦门特殊规则
  的模拟成本高。先构建有价值网络的 rollout 评测，再决定是否投入。
